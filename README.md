# 车队日志策略发布平台（题目09）

Go + SQLite 的服务端渲染单体应用（后端完成前端，无 JS 框架）。

## 运行

```bash
go run ./cmd/server        # 默认 http://localhost:8080，DB=data.db
```

环境变量：`DB_PATH`（数据库文件路径）、`ADDR`（监听地址）、`SESSION_SECRET`（会话签名密钥）、`ACK_TIMEOUT`（回执超时秒数，教学用，默认 60）。

## 预置账号（登录页选择即可）

| 账号 | 角色 |
|------|------|
| 张研发 / 赵研发 | 研发申请人 |
| 李负责 | 审批负责人 |
| 王运营 | 发布运营 |

预置车队：V1~V5，原始间隔 60s（V2 初始离线）。车辆回执令牌：`vtok-V1` … `vtok-V5`（车端 API 与模拟器页共用）。

## 业务规则（对应题面）

1. 研发申请：原因必填，间隔 10~300 秒；自己不能审批自己；批准/退回后可修改再提交。
2. 同一车队同时只能有一个未结束的发布活动。
3. 试点 2 台 → 两台全部成功后运营确认推广至剩余 3 台；试点失败或超时则暂停推进，负责人可决定停止（停止保留已生效值）。
4. 恢复：运营发起 → 负责人批准 → 执行（逐车恢复活动前生效值）→ 负责人记恢复完成。
5. 车端回执：令牌鉴权；成功/失败/超时逐车留痕；重复成功不重复记账；旧版本不能覆盖新版本；跨车版本回执拒绝；超时后迟到成功可更新该车结果并保留超时历史。
6. 核查：逐车下发记录 + 回执 + 操作审计。

## 结构

```
cmd/server            入口装配
internal/model        领域模型与状态常量
internal/store        SQLite 打开/迁移/预置数据
internal/service      业务规则（状态机、版本、鉴权、超时）
internal/web          服务端渲染页面 + 车端 API（Go embed 内嵌模板与样式）
```
